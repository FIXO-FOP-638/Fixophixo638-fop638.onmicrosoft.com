## Custom MCP connectors

If you need to connect Grok to a service not available in the catalog, you can bring your own [Model Context Protocol (MCP)](https://modelcontextprotocol.io) server. MCP is an open standard that lets AI assistants interact with external tools and data sources through a unified protocol.

With a custom MCP connector you can:

* Expose any internal API, database, or SaaS tool to Grok.
* Define your own tools with custom schemas and logic.
* Control authentication and access on your own infrastructure.

To add a custom MCP connector:

1. Go to [grok.com/connectors](https://grok.com/connectors).
2. Click **New Connector**, then select **Custom**.
3. Enter the MCP server URL and complete any required authentication.

Grok will discover the tools your MCP server exposes and make them available in conversations, just like the built-in and catalog connectors.

Your MCP server must be reachable over the public internet. If it is running on your local machine, you will need a tunneling service to make it accessible. See [Custom MCP Server Tunneling](/grok/connectors/custom-mcp-tunneling) for setup instructions.

### ❌ Error: GitHub Action Fallido (`auto-label-merge-conflicts`)

**Diagnóstico:**  
El workflow falla repetidamente en ramas con caracteres especiales (`#PHIXOR18.md`, `SECURITY`).

**Causa raíz:**
- Los nombres de ramas con `#` rompen la sintaxis YAML si no se citan.
- El token `GITHUB_TOKEN` puede carecer de permisos de escritura.
- Indentación incorrecta o lógica de eventos incompatible.

**Solución – Workflow corregido:**

```yaml
name: Auto-label merge conflicts
on:
  push:
    branches:
      - '#PHIXOR18.md'
      - 'SECURITY'
      - '##FoP-638-#PHIXOR13.md'
  pull_request:
    types: [opened, synchronize]

permissions:
  contents: read
  issues: write
  pull-requests: write

jobs:
  auto-label:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Label merge conflicts
        uses: actions/github-script@v7
        with:
          script: |
            const pr = context.payload.pull_request;
            if (!pr) return;
            const hasConflicts = false; // Reemplazar con lógica real
            if (hasConflicts) {
              await github.rest.issues.addLabels({
                owner: context.repo.owner,
                repo: context.repo.repo,
                issue_number: pr.number,
                labels: ['merge-conflict', 'urgent']
              });
            }
```

🛠️ README DE SOLUCIÓN — PHIXOR18.md + SECURITY

📋 Diagnóstico del fallo

El workflow auto-label-merge-conflicts.yaml falla porque:

1. Permisos insuficientes: el token por defecto no tiene pull-requests: write.
2. Job triage falla en 22s: probablemente la acción no encuentra el PR o no puede etiquetarlo.
3. Attempt #3: reintentos automáticos que también fallan por la misma causa raíz.
4. Branch #PHIXOR18.md: el # en el nombre de la rama rompe algunas acciones de GitHub.

✅ Solución paso a paso

1. Corregir permisos del workflow

En tu archivo .github/workflows/auto-label-merge-conflicts.yaml:

```yaml
name: Auto-label merge conflicts

on:
  pull_request:
    types: [opened, synchronize, reopened]

permissions:
  contents: read
  pull-requests: write  # ← ESTO ES LO QUE FALTA

jobs:
  triage:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - name: Check for merge conflicts
        uses: eps1lon/actions-label-merge-conflict@v3
        with:
          dirtyLabel: "conflicts"
          repoToken: "${{ secrets.GITHUB_TOKEN }}"
          commentOnDirty: "🚨 Este PR tiene conflictos. Por favor resuélvelos antes de continuar, mi SR GAZOO RACING."
```

2. Renombrar la rama #PHIXOR18.md

GitHub no ama los # en nombres de rama. Sugerencia:

```bash
git branch -m "#PHIXOR18.md" "phixor18-md"
git push origin -u phixor18-md
git push origin --delete "#PHIXOR18.md"  # solo cuando estés seguro
```

3. Añadir un step de diagnóstico

```yaml
      - name: Debug context
        run: |
          echo "PR: ${{ github.event.pull_request.number }}"
          echo "Branch: ${{ github.head_ref }}"
          echo "Repo: ${{ github.repository }}"
```

4. Aplicar a SECURITY también

Duplica el workflow con on: push: branches: [SECURITY] o usa un matrix con ambas ramas.

Diagnóstico Técnico

Caracteres especiales en nombres de ramas: Nombres como #PHIXOR18.md o ##FoP-638-#PHIXOR13.md contienen #, el cual es interpretado por el intérprete de comandos y la API de GitHub como un comentario o fragmento URI, rompiendo la resolución de refs.

Permisos de GITHUB_TOKEN restringidos: Las políticas actuales de GitHub Actions ejecutan los workflows en modo lectura por defecto. Para etiquetar PRs o buscar conflictos, el token requiere permisos explícitos de pull-requests: write.

Solución: .github/workflows/auto-label-merge-conflicts.yaml

Reemplaza el contenido de tu archivo workflow con el siguiente bloque configurado con permisos y manejo seguro de tokens:

name: "Auto-label merge conflicts" on: push: pull_request_target: types: [synchronize, opened, reopened, labeled, unlabeled] permissions: contents: read pull-requests: write issues: write jobs: triage: runs-on: ubuntu-latest steps: - name: Label Merge Conflicts uses: eps1lon/actions-label-merge-conflict@v3 with: dirtyLabel: "conflicts" repoToken: "${{ secrets.GITHUB_TOKEN }}" retryAfter: 5 retryMax: 3
